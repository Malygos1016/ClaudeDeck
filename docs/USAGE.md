## 首次启动

双击 `start_claudedeck.bat`。没有任何窗口弹出是正常的——服务藏在系统托盘里(右下角琥珀色圆灯图标)。双击图标开界面,右键有"打开界面 / 查看日志 / 退出"。

首次启动会全量扫描你的全部会话历史建索引,几秒到一两分钟。之后每 60 秒增量扫描,只读新增内容,几乎无感。

## 找回一段旧对话

1. 会话页顶部搜索框输入关键词(支持中文,三字以上走全文索引最快;一两个字自动转模糊匹配),回车。
2. 结果按会话分组,每条命中显示上下文片段。**点击命中片段**直接进入聊天视图并定位到那一轮,高亮闪烁提示。
3. 想继续这个会话:点行尾"**恢复 ▶**"——新开一个 Windows Terminal 标签、cd 到原项目目录、执行 resume,信任弹窗已提前替你按掉。或点"复制命令"拿到完整命令自己找地方粘贴。

注意两点:大会话 resume 时 Claude Code 可能弹"摘要/完整原样"选择,按 `2` 回车加载完整对话(官方无自动化开关);正在某窗口里开着的会话不允许重复 resume(会被官方并发检测杀掉),界面会直接告诉你它开在哪个窗口。

## 重启电脑后找回所有工作现场

会话页默认按"最近活跃"排序,每行有"已停止"徽章并悬浮显示停了多久。重启后依次对最上面几行点"恢复 ▶"即可,每个会话回到各自的项目目录。

## 同时盯多个窗口

看板页"运行中窗口"区,每个开着的 Claude Code 窗口一张卡:

- **琥珀呼吸灯 = 忙碌**(正在生成);
- **红灯 = 等待你**(要你输入或授权,最需要看见,排最前);
- **绿灯 = 空闲**。

顶栏灯条在**每一页**都亮着,写着各窗口名字和状态,不在看板页也能瞟到谁在等你。

卡片带"**后台驻留**"虚线徽章的不是窗口——是 fork 到后台、由 daemon 养着的无窗会话(标题里的 `⑂` 是 fork 标记)。这类任务在"后台作业"区能看到它在等什么;不要了就在终端跑 `claude agents` 停掉。

## 看懂配额窗口

看板页"配额窗口(5h)"面板。Claude 的用量限制按 5 小时窗口计,面板显示:

- **当前窗口**的起止与剩余时间(整点锚定,语义对齐 ccusage);
- **已用 tokens**(含缓存)与非缓存量;
- **燃烧率**(tokens/分钟)和按此速率推算的窗末总量;
- **判定**:参照你自己历史窗口的最大用量,外推是否会在本窗口内触顶。

务必理解:参照物是"**你的历史峰值**",不是官方额度(官方从不公布数字)。它回答的问题是"今天这一窗烧得比我平时猛多少",判定"×点×分触顶"意思是"到那时会超过你史上最猛的一窗"。下方条形图是近 12 个窗口的用量对比,当前窗口高亮。

## 对付 30 天自动清理:封存与还原

Claude Code 默认删除 30 天无活动的会话记录(改 `cleanupPeriodDays` 只能全局延后,且很多人不知道这回事)。ClaudeDeck 的策略是**手动封存 + 事后可救**:

- **封存**:会话行或详情页点"封存"——把 transcript 与伴生文件拷贝到独立归档目录(默认 `C:\CoreWork\ClaudeArchive`,可在设置页改)。做完一件重要事情就顺手封存,这是唯一的备份途径。
- **被清理之后**:会话列表里该行变为"源已清理"徽章,内容仍可搜索阅读(读的是归档副本)。
- **还原**:归档页(或详情页)点"还原到 projects"——副本拷回原位,resume 重新可用。注意官方清理器在 Claude Code 下次启动还会跑,还原后尽快 resume 一次刷新活跃时间。

归档页还能看归档区总量、按会话浏览全部封存副本。

## 管理 Codex / pi / Crush 的会话

装了这些工具的机器,它们的历史会话自动进同一个索引:

- 会话页 **provider 下拉**(全部/claude/codex/pi/crush)筛选;非 claude 的行带彩色小徽章。
- 搜索、聊天视图、导出 MD 与 claude 会话完全一致。
- "恢复 ▶"按各家能力:codex 拉 `codex resume <id>`;pi 拉 `pi --session <id>`;**crush 没有命令行级恢复**,按钮会在项目目录打开 crush 的 TUI,你在它的会话列表里选(会有提示)。
- 封存/归档、实时状态灯、配额窗口不适用于非 claude 会话:前者因为它们的数据目录由各工具自行管理(无 30 天清理问题),后两者因为只有 Claude Code 有运行注册表,配额是 Anthropic 的事。

## 清理磁盘与删除项目

看板页"磁盘占用"分两块:`~/.claude` 分目录、按项目聚合(清理决策的主视角——哪个项目占了多少、多久没动)。

要彻底删掉一个项目的所有会话:设置页"危险区"→ 选项目 → **输入项目目录名确认** → purge。流程是先把该项目全部会话强制封存到归档区,再调用官方 `claude project purge --yes`。也就是说 purge 之后你仍然能在归档页搜到和读到这些会话,只是官方目录里没有了。

## 托盘、自启与配置

- **托盘**:`start_claudedeck.bat` 无窗启动;重复双击不会起第二份服务(单实例保护,只帮你开个浏览器页)。退出走托盘右键。
- **CCTopBar 桌面顶栏**:默认开启,随托盘自动出现在主屏顶端(AppBar 占位,最大化窗口自动让位)。左键格子聚焦对应终端标签,右键格子重命名,右键空白处可关闭;托盘菜单"CCTopBar 顶栏"可开关(记忆在 `config.json` 的 `topbar_enabled`)。
- **开机自启**:项目目录 PowerShell 跑 `.\autostart.ps1 -Enable`(计划任务,登录时静默拉起);`-Disable` 移除,`-Status` 查看。
- **配置**:设置页可改,或直接编辑项目根 `config.json`:

| 键 | 默认 | 说明 |
|---|---|---|
| `port` | 8737 | 服务端口(改后重启生效) |
| `archive_dir` | `C:\CoreWork\ClaudeArchive` | 归档目录,建议放到大盘 |
| `scan_interval_seconds` | 60 | 增量扫描间隔 |
| `claude_home` | `~/.claude` | Claude Code 数据目录 |
| `codex_home` / `pi_home` / `crush_projects_json` | 各官方默认位置 | 多 provider 数据入口,目录不存在自动跳过 |
| `claude_exe` | npm 全局安装路径 | resume 拉起用的 claude.exe 全路径 |

## 故障排查

- **端口被占,起不来**:托盘右键"查看日志"看 `tray.log`;改 `config.json` 的 `port` 重启。服务绝不自动漂移端口。
- **出现标题为 `pythonw.exe` 的黑窗口,关掉托盘就死**:老版启动脚本 + 部分 uv 版本的组合问题(uv 给 venv 造的 pythonw 垫片是控制台子系统)。`git pull` 拿到新版脚本即根治(隐藏式启动,不依赖垫片子系统);已挂开机自启的机器重跑一次 `.\autostart.ps1 -Enable` 更新任务。
- **看板出现"泛状态追踪模式"徽章**:正常时每张窗口卡按"进程号+进程创建时间"双因子认定存活;全体对不上号时(常见于刚开机、注册表里全是旧记录)临时切换为宽松判据,灯的可信度略降,通常几分钟内自动恢复,无需处理。
- **搜索结果missing/不全**:设置页"重建索引"(索引是纯缓存,重建无副作用,几秒到几分钟)。
- **resume 出来的窗口有异样**:确认没有从别的终端里"套娃"启动服务;ClaudeDeck 拉起前会剥离父环境里的着色与嵌套标记,若仍异常请提 issue 附 `tray.log`。
- **改了代码/更新了版本页面没变化**:服务端带 `no-cache`,正常刷新即可;极端情况 Ctrl+F5。
